# Mandatory Concept Review Protocol

## Required review areas

1. Core user problem
2. Broad versus focused beta positioning
3. Target audience
4. Topic taxonomy
5. Unsupported and high-risk topics
6. Scholarly-source coverage
7. Query clarification
8. Eligibility criteria
9. Free teaser value
10. Premium report depth
11. Price-value fit
12. Stripe conversion flow
13. Failed report/refund process
14. Report retention and sharing
15. Privacy
16. Legal seller and tax
17. Support operations
18. Analytics and success criteria
19. Cost limits
20. Beta launch strategy
21. Domain/email/deployment
22. AXIA4 relationship

## One-question rule

Each message must contain exactly one decision question.

Format:

**Entscheidung**  
What needs to be decided.

**Warum wichtig**  
Why it affects usability, safety, cost, or launch success.

**Empfehlung**  
Claude’s clear recommended choice.

**Optionen**  
Maximum three concise options if useful.

**Frage**  
One direct question only.

Then wait.

## Mandatory open decisions

Ask only where not already settled:

- initial beta topic categories
- whether high-risk health topics are excluded in beta
- exact public example-report topic
- exact Premium Report minimum depth
- paid-report retention period
- whether secure links may be shared
- free-search usage limit
- maximum included studies
- source-coverage threshold
- price confirmation after cost estimate
- support address and response time
- legal seller
- tax-inclusive wording
- email provider
- analytics provider
- closed-beta size
- first evaluation milestone
- continue/optimize/pause/stop thresholds

## Completion documents

- `FINAL_CONCEPT_DECISIONS.md`
- `FINAL_MVP_SCOPE.md`
- `SOURCE_COVERAGE_MATRIX.md`
- `OPEN_RISKS.md`
- `IMPLEMENTATION_PLAN.md`
- `STATUS.md`

Then request one implementation approval.
